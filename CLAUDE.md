# Idle Merchant Guild — Claude Notes

## Project Overview
Unity 2D idle game. A merchant guild that hires adventurers, porters, and manages a shop. Dungeon layers produce loot, porters transport it, the shop sells it to customers.

**Engine:** Unity (URP, UI Toolkit, Spine/SpriteLibrary for modular characters)
**Language:** C# (.NET via Unity)
**Working directory:** `Assets/` (open scripts relative to here)

---

## Architecture

### Singleton Pattern
Persistent cross-scene managers use `PersistentSingleton<T>` (`Scripts/Managers/PersistentSingleton.cs`).
Access via `GameManager.Instance`, `UnitManager.Instance`, etc.

### Event System
`Scripts/Core/GameSignals.cs` — static C# events for decoupled communication.
- Raise: `GameSignals.RaiseGoldEarned(amount)`
- Subscribe: `GameSignals.OnGoldEarned += handler`
- Always unsubscribe in `OnDestroy` to avoid leaks.

### Entity Hierarchy
```
EntityBase (MonoBehaviour)
  └── EntityStateMachine<TState>   ← staggered AI tick at 10Hz
        ├── AdventurerAgent        (State: Idle/Wander/Seek/Attack/Hit/Dead)
        ├── MobAgent
        └── PorterAgent
  └── CustomerAgent
```

### Stats System (`Scripts/Entities/Stats/`)
- `BaseStats` — raw values from `EntityDef`
- `StatsMediator` — holds `IStatModifier` list, dirty-flag caching
- `Stats` — cached property access (`entity.Stats.MoveSpeed`, `.AttackDamage`, etc.)
- Add buffs via `entity.Stats.Mediator.AddModifier(modifier)`
- Cache auto-invalidates; no manual refresh needed.

### Data (ScriptableObjects)
- `EntityDef` → base entity data (prefab, stats, sprite libraries, colour palettes)
- `AdventurerDef : EntityDef` → adventurer-specific (health, revive delay, states)
- `MobDef : EntityDef`, `PorterDef : EntityDef`, `CustomerDef : EntityDef`
- `SkillDef`, `TraitDef`, `ItemDef` — content data
- Create via `Assets > Data > ...` menu

### Unit Management
`UnitManager<T>` (abstract) — hiring, spawning, tracking, capacity per dungeon layer.
Implements `IUnitManager` (defined in `Scripts/Core/GlobalInterfaces.cs`).
Concrete: `AdventurerManager`, `PorterManager`, `MobManager`.

### UI
- **UI Toolkit** (UXML/USS) — all panels use `UI Toolkit`
- Panels live in `Scripts/UI/Panels/`; each has a controller inheriting `BasePanelController`
- `UIManager` — top-level panel orchestration
- `GameSignals` drives reactive UI updates (gold display, unit counts, etc.)
- Design tokens: `Scripts/UI/GlobalVariables.uss` — colour / text / spacing / font-size `--vars` mirrored from Figma; consume via `var()` in `.class`/`#id` rules
- Reusable Button: `Scripts/UI/Components/Button.uss` + `Button.uxml` — tint-driven 9-slice variants (`btn-primary` / `-secondary` / `-success` / `-danger` / `-disabled`)
- Top-nav board badges: `UIManager.SetBoardBadge(badge, visible, wiggle)` — shared badge toggle + ~5s button tilt-wiggle (scheduled item kept in the badge's `userData`); used by the cursor and hiring boards and the Units bookmark (promote-ready count via pure `AdventurerManager.CountPromoteReady`, gold dirty flag)
- Book pages (`BookPanelController`, tabs 0 Roster · 1 Guild · 2 Inventory · 3 Crafting · 4 Settings · 5 Cursor · 6 Contracts) share: `.book-subhead` rule·label·rule header (`BookPanel.uss`, `--subhead-*` tokens), `UI/BookStamp.cs` slam-on / dither-off stamp (Inventory FOR SALE, Crafting CRAFTING), `UI/Components/StatusFrame.cs` (Painter2D progress sweep; idle/crafting/blocked/capped/locked)
- Main menu = `UI/Panels/Pause Menu/PauseMenuController` (`Pause_Panel.uxml`, panel id `Pause_Panel` so the scene's Esc binding → `UIManager.OnCancelPressed` still finds it; Esc closes the top modal first): the closed book cover (`Sprites/UI/Main UI/book cover.png` 2×, `logo.png` 4×, `Tools/snap_logo.py`) over the paused guild. Opens instantly on cold boot; open = `PauseGame`, HUD (`TopNavigation`, `MilestoneTracker`) fades, camera ortho ÷ `menuZoom`, adventurers + porters hidden via `Renderer.forceRenderingOff` (swept every frame while up — the restore spawns after boot and unit code toggles its own renderers; only the ones it forced come back) while station workers and the shopkeeper keep animating (`WorkshopProp` worker Animator + lit loop, `LootPile`'s shopkeeper (`Guild/Shop/MiniMerchant`, `Prefabs/Entities/Customers/Merchant Shopkeeper.controller`: Idle → `Sale` trigger → idle2 flourish → Idle, fired when a sold item lands on the buyer) Animator on unscaled time); Continue reverses it and unpauses at the end. `PauseMenuController.AfterContinue` defers things to the first Continue (welcome-back uses it). Settings = book tab 4 over the cover (cover hides on `OnLoseFocus`). New Guild wipes the save and reboots: every DontDestroyOnLoad root destroyed + old scene deactivated, one frame, then `LoadScene` (same frame = new singletons meet dying Instances); statics that outlive a reload need resetting there (`DecorSlot.ResetStatics`)
- Panels animate on unscaled time (`BasePanelController.GetDeltaTime`) so the book still opens over the paused menu; `GameManager.PauseGame` never captures `Time.timeScale` (the player's speed lives in `SetTimeScale`), and hit-stop doesn't restore over a pause
- **UI Toolkit gotchas:** no `gap` (use margins) · no `box-shadow` / `text-shadow` · `var()` resolves only in USS rules, never inline `style=""` (inline `var()` throws an NRE that aborts the whole `CloneTree` → blank panel) · a margin reset must be a bare `*`, not `#scope *` (id specificity wipes class margins)

### Shop Pipeline
`Shop/Inventory.cs` → gold source of truth (use `Inventory.Instance` for gold ops)
`Shop/ShopManager.cs` → orchestrates shelf, counter, sales
`Shop/SalesManager.cs` → sells items to customers; `TryPickDesiredForCustomer` resolves a want (the def's `preferredItems` shopping list first — Villager minerals/bones, Potion Lady reagents, Adventurer gear, Noble jewellery + relics — then the preferred category, else best affordable anywhere) and reports a `WalkoutReason` (`NoStock` / `TooExpensive`) on failure; within a scan the pick is the priciest affordable item in stock, bought as many as budget and stock allow up to `batchRange.y`; `batchRange.x` is **not** a gate (failing below it meant nothing above tier-one gear ever had a walk-in buyer: 2-piece adventurers can't pair anything over 1500, 5-piece nobles can't take five plates). A customer who can afford one of something buys what they can; walkouts are stock, budget-below-cheapest-unit, or patience
`Shop/Inventory.cs` floors → `SetFloor/GetFloor` "keep at least N" per item; respected by sales and crafting (UI label KEEP)
`Shop/LootPile.cs` → stock heap behind the counter; `FlySale` relays a sold item pile → counter → homing onto the buyer (`CustomerCarryDisplay` shows the carry on arrival); shopkeeper flips toward the bin while a leg is in flight
`Shop/LootPile.cs` is also the Inventory shortcut: a trigger `BoxCollider2D` on `Guild/Shop/Loot Pile` (bin + heap), hover = outline bit 2 on the bin and heap sprites (`SetHover`), click = ClickerManager priority 3a → `BookPanelController.OpenToTab(2)`
`Shop/Shelf.cs` → holds items for sale (fully commented out)
`Shop/QueueController.cs` → customer queue; `maxQueueAmount` (5 in the scene) + `slotsPerQueueRoom` 2 per owned Queue Room rank, same event hook
- **Shop upgrades** `Resources/Guild Upgrades/Queue Room I–III` (`UpgradeType.QueueRoom`, 4k/10k/25k, ★1/2/3) and `Quick Counter I–III` (`UpgradeType.QuickCounter`, 6k/15k/36k, ★1/2/3), ranked via `requiredUpgrade` like Porter Lodging; icons `Sprites/UI/Book UI/Content/Icons/upgrade-queue-room.png` / `upgrade-quick-counter.png` (20 px, drawn by hand in the smithy icon's palette). The Guild page shows **one card per ladder** (`GuildUpgradePanel.VisibleUpgrades`: ladder = `UpgradeType` for ranked upgrades, the depth for `layerSpecific` ones (`LadderKey`); steps sorted by `targetLayer` → type → star → gold; the card is the first unowned step, or the last step as Owned; completed ladders sort to the bottom, the rest by star → gold), so Queue Room I becomes Queue Room II on purchase and each depth has one card stepping Elevator → Teleporter; cards rebuild when the visible set changes, else just re-gate
`Shop/CounterService.cs` → serves the queue head: `serveTime` (3 s, minus `serveTimePerRank` 0.6 s per owned Quick Counter rank, floor 0.5 s; `effectiveServeTime` recomputed on `ProgressionManager.OnUpgradePurchased`) then the sale; **click to serve** = clicking the customer being served (`Serving`, ClickerManager priority 2b, hover outline bit 2 via `CustomerAgent.SetHoverOutline`) lands the sale now with `serveBonus` (15%) extra (a "+15%" float + gold number), banked on coin arrival via `ShowGoldGain` (active income — never `OnItemSold`, so offline rates ignore it); an LMB glyph (TMP sprite asset `LMB`, the `RMB` one mirrored) bobs over the customer at the counter until `ClickerManager.Serves` (saved in `ClickerSave.serves`) reaches 3

### Crafting
`Crafting/CraftingManager.cs` (scene singleton, not persistent) → a recipe runs iff it is pinned in a station slot. Each station (`RecipeDef.station`: Forging 2 base slots / Smithy 1 / Arcane Workshop 1) holds an ordered `RecipeDef|null` list; jobs key by (station, slot), one per slot; the same recipe may fill several slots and crafts in parallel. Slot order is the priority (no priority field). Per-recipe output cap (default 25, 1–999) counts stock + jobs in flight. API: `GetSlots` / `AssignSlot(station, i, recipe|null)` (cancels + refunds that slot's running job) / `PinToFirstFreeSlot` / `ClearRecipeSlots` / `HasFreeSlot` / `GetSlotState` / `GetSlotProgress`; `IsRecipeEnabled` ≡ pinned somewhere, `EnableRecipe` = pin unless already pinned (progression unlocks). `BuyStationSlot` appends an empty slot, 2500×1.6^bought. `GetBlockReason` → `No station` / `At cap` / `Missing materials`. Signals `OnCraftStarted`, `OnCraftingConfigChanged` (every slot/cap change)
`UI/Panels/Crafting Menu/CraftingController.cs` → book Crafting page (tiles per layer on torn sheets, inventory-style right page; foot-plank stamp = pin to the station's first free slot — a full station shakes the plank and reads "<Station> full" — dither-off clears its slots; "<Station> · slot N" line)
`Crafting/WorkshopProp.cs` → station props in the guild interior (`Guild/Shop/Workshops`: Forging bay at the right end by the exit, Smithy left of it, Arcane Workshop left of the counter): frame 0 cold until the upgrade is owned, then a 6 fps lit loop; hover = outline bit 2; click (ClickerManager priority 3) opens the Workshop panel
`UI/Panels/Workshop/WorkshopPanelController.cs` → modal Workshop panel (`WorkshopPanel.uxml/.uss`, instanced in MainUI.uxml): stone wall + beam, the clicked prop's frames at 3× as hero, iron-plate slots (click → "Assign recipe" dropdown, "also in slot N" when stacked, Clear slot), "+ Slot" buy button; unowned station shows the cold frame + "Buy the <Station> in the Guild book"

### Contracts & Seals
`Managers/ContractManager.cs` → 3 offers rotating every 10 min, accept 1 (never expires); Deliver (raw items, fulfilled from stock) / Hunt (kills on a staffed layer) / Patronage (customers served). Target snapshotted at roll = max(rate × 5–10 min, stock × 30–40%, floor). Deliver gold = target × sellPrice × 1.6; counters pay 50% of passive gold/min over the work time. Seals: 10, or 20–30 for layer ≥3. Also owns the Guild Seal balance + seal shop (Recruitment Favor 50, Rush Order 20). Seals also come from star awards (30/50/80/120/200, `ProgressionManager`) and `StarMilestoneDef.sealReward`. Signals `OnContractAccepted/Completed`, `OnSealsChanged`. Design: `CONTRACTS_DESIGN.md`
`UI/Panels/Contracts/ContractsPage.cs` → book Contracts tab; the active contract also rides the HUD milestone tracker. **Notices** (left page, under the offers, compact ledger rows because the page has no height for more cards): player-posted ads = `EventDef`s in `Resources/Events/Ads/` with `playerOnly` (never rolled, don't count toward `maxActive`), loaded by `EventManager.Ads`; `Ad_Crowd` (`EventKind.Advertise`: ◀ pick ▶ a walk-in def from `CustomerSpawner.AdvertisableDefs()` — candidates past their star gate, never royals — whose spawn weight is × `rateMultiplier` 3 for 5 min via `CustomerSpawner.BoostWeight`, multiplied into `PickBoosted`, never an override) and `Ad_Sale` (`EventKind.FeaturedItem`: pick a sellable item in stock; `SalesManager.Featured` is tried first by every want pick with `featuredChance` 0.6). Post = `EventManager.TryPost(def, customer|item)`: cost `CostOf` = `goldCostMinutes` 2 × passive `SaveManager.GoldPerMin` (≥ `minGoldCost` 500) via `TrySpendGold`, one of each at a time, `cooldownSeconds` 600 after; the row shows the remaining / cooldown clock on the button, the HUD card shows `ActiveEvent.Icon` (item icon / `CustomerDef.portrait` — Frame_0 of one look's sheet) and `note`. Not saved, like every event
`Shop/CaravanManager.cs` → the Caravan, a stock valve: every 8 min game time a wagon (scene singleton on `Guild/Shop/Caravan`; drives in from 75 units left of its park — past the camera's left bound — over 6 s with the wheels turning, and back out the same way) offers 5 Guild Seals for 70% of the surplus above floor of the raw item with the highest (stock − floor) × sellPrice; no visit if that qty < 20; offer open 2 min, Accept = `TryRemove` + `GrantSeals` (no gold, no `OnItemSold` → not passive income). Click opens `UI/Panels/Caravan/CaravanPanelController` (reuses the Workshop `wp-*` shell). Signal `OnCaravanChanged`; saved as `SaveData.caravan`
`Systems/Spawners/CustomerSpawner.cs` → weights Villager 0.5 / Herbalist 0.4 / Bulk Trader 0.2 / Adventurer 0.35 / Noble 0.12 / Collector 0.09 (≈ 30 / 24 / 12 / 21 / 7 / 5 % at ★3+), per-archetype alive caps `maxAdventurer` 8 / `maxNoble` 5; `maxAlive` 40 in the shop at once (was 10; the queue's `maxQueueAmount` is the real bottleneck, extra customers browse); customer defs in `Prefabs/Entities/Customers/` (Villager Man (looks: Villager Man + Villager Woman + Peasant) / Potion Lady (displayName Herbalist; looks: Old Woman + Old Man) / Bulk Trader = Commoner — the trader (Dwarf Miner / Hunter looks) buys 10–20 minerals at `priceMultiplier` 0.8, weight 0.2, Adventurer Customer ★2 (looks: Swordsman / Archer / Spearman / Crossbowman from the Humans pack + Elf Swordsman / Spearman / Mage + Dwarf Warrior / Rifleman — class rigs use HalberdMan / ShieldMan / Mage / Thief, so customers never look like your own heroes), Noble ★3 (weight 0.12), Collector ★3 (weight 0.09; Noble archetype, Elf Mage / Arcane Archer looks: rare raws — Infernal Core, Demon Horn, Soul Shard … — 1–2 at ×2; `CustomerDef.priceMultiplier` scales the counter price and the want pick's budget), King / Queen / Prince / Princess = Royalty ★5: weight 0.005 each, budget 15–30k, wants the top crafted pieces; royals never roll on their own — the Royal Visit event calls `SpawnRoyalVisit`: a random lead plus company via `SpawnRoyalParty`, solo 30% / pair 50% / the whole family, distinct looks, ignoring `maxAlive`, announced with a float); a def's `animatorOverrideController` list is its looks, one picked per spawn (Noble = `Noble Man` + `Noble Woman` over `Sprites/Customer/Villagers/MiniNobleMan` / `MiniNobleWoman.aseprite`). A new look = clone `Potion Lady.overrideController` with the aseprite guid swapped (clip fileIDs are tag hashes, identical across Minifolks files). **An override controller must hold only pairs whose original clip is in `Customer Controller`** (idle / walk / work): stale pairs keyed on clips the base no longer has made Unity drop the whole override at runtime whenever the stale override side resolved to a real clip, so every Humans / Dwarves / Elves / Pirates / Royals look silently played the Miner sheet (found 2026-11-06). Rebuild with `GetOverrides` → filter by the base's `animationClips` → `ApplyOverrides`. Guarded by the EditMode test `Tests/Editor/CustomerLookTests.cs` (asmdef `IdleMerchantGuild.EditorTests`; Test Runner or MCP `run_tests`), which reads the raw serialized `m_Clips` — `GetOverrides()` returns one entry per base clip and never shows a stale pair, and an edit-mode Animator plays a broken override fine (the drop only happens in play), so neither can catch it

### Events
`Events/EventManager.cs` (scene singleton `System/EventManager`) → timed world events from `Events/EventDef` assets in `Resources/Events/` (`kind`: RushHour = customer spawn rate × `rateMultiplier` via `CustomerSpawner.RateMultiplier`; AdventurerParty = `partySize` × `partyCustomer` arrive together via `SpawnParty`; RoyalVisit = `SpawnRoyalVisit`, the only way royals arrive now; Delegation = every `partyMembers` def once — Dwarven Delegation ★4 = Dwarf King + Bear Rider + Shieldbreaker wanting forged pieces, Elven Court ★5 = Elf Queen + Pegasus Rider + Warden wanting arcane pieces, all Royalty-archetype defs that aren't spawner candidates; PirateRaid ★3 = Captain + Crew + Gunner + Harpooner spawned the same way, each given an `Events/PirateRaider` (CustomerAgent off, walks to the loot pile, grabs `stealPercent` (15%, ≥1) of one random stack per `stealInterval`, flees after `carryMax` grabs — 12 grabs, so an unattended raid costs ~15% of a dozen stacks, grabs stack as icons over their head; click = priority 2c `Kill` → items fly back to the pile, `ClickHitVFX.PlayKill` + Kill sfx, the def's `deathClip` (the sheet's death tag, played through `AnimationPlayableUtilities.PlayClip` because the customer controller has no Dead state; graph destroyed on pooling) then despawn; rolls only while the camera is at the shop, `ShopOnScreen`). Roll every `rollMin`–`rollMax` (150–240) game seconds, weighted over unlocked (`unlockStar`) off-cooldown defs not already running (unless `stackable` — Adventurer Party, no cooldown, so two can be in at once), ≤ `maxActive` 2 (`outsideCap` defs — the Pirate Raid, cooldown 240 — roll past the cap and don't count toward it, so a raid can land during a royal visit); parties end when every member has left (members are matched by `EntityBase.SpawnSerial`, bumped per `Init`, so a pooled customer reused as a new walk-in no longer counts), else at `durationSeconds`; `Fire(def)` for the debugger. Nothing is saved (reload drops events + cooldowns). Signal `OnEventsChanged`. **Royal audience** (`Events/RoyalAudience.cs`, on the lead of a RoyalVisit / Delegation, CustomerAgent off like the raider): walks to the dais left of the counter and waits `audienceSeconds` (60); click (ClickerManager priority 2b', hover outline) → `UI/Panels/Audience/AudiencePanelController` (Workshop shell): the fancied piece (random `preferredItems` entry in stock) at `fanciedMultiplier` 3× list, the two priciest other sellables at `altMultiplier` 1.5×, Decline; `Present` = stock out, gold via `ShowGoldGain` (active income) + `audienceSeals` 20, the royal leaves carrying it; timeout = "Snubbed!", leaves empty-handed, the event's cooldown × `snubCooldownMultiplier`. `ActiveEvent.note` is the card's live line ("Click the Queen to present · 0:42")
`UI/Panels/Events/EventTracker.cs` → HUD list at `left: 16, top: 129` (mirror of the milestone tracker; `EventTracker.uxml/.uss`, instanced in MainUI.uxml, faded with the HUD by the main menu): one plank card per active event (icon, name, `effectLine`, draining bar, "N left" for parties); click = `EventManager.FocusOn`: `LockOnto` the event's lead customer (first party member still in the shop; manual scroll releases it), else `JumpTo(FocusPoint)` (counter, or the loot pile for a raid); the Caravan rides the same list while parked (own `LeaveIn` clock, click = `LockOnto` the wagon while it drives) so it's visible from down a depth

### Adventurer Classes (`Entities/Adventuers/ClassCatalog.cs`, design in `CLASSES_DESIGN.md`)
- `ClassLine` enum (Novice, Warrior, Guardian, Rogue, Mage — serialized ints, append only); one `AdventurerDef` per line × tier in `Prefabs/Entities/Adventurers/Classes/` + `Lvl 1 Novice`. Tier = the def's `rank`; `displayName` = class name, `description` = role line, `classIcon`, `damageMultiplier` / `hpMultiplier` (applied in `BaseStats.FromEntityDef` / `AdventurerDef.MaxHealth`); Rogue = 1.4× attack speed (`attackInterval` 0.71), Mage = slower heavy hits (`attackInterval` 1.25) at range 6 with a homing fireball (`AdventurerDef.projectilePrefab`)
- `Resources/ClassCatalog.asset` (`ClassCatalog.Instance`) lists every hireable adventurer def + tier weights, unlock boost and hire premium. The hire board builds adventurer pools from it (one per def, gated `rank <= maxUnlockedLayer`); AdventurerManagers' `hireableDefs` are empty and unused — porters still use theirs
- `AdventurerAgent.Promote(line)` = AdvanceRank + `SetClassDef(next tier)` (base stats, max HP, skills swap; level/trait modifiers stay). A Novice must name a line (Roster "Choose a path" picker); `NeedsPathPick` (Novice above Wood) → free `ChoosePath(line)`, counted by `CanPromote` with `PromoteCost` 0
- **Moving between depths** (Roster): `AdventurerManager.Move(agent, toManager)` / `Swap(a, b)` respawn the unit on the target depth by the save round trip (def, identity, traits, looks, rank, level, XP kept; HP and position reset), new instance spawned before the old is removed; `MoveBlocker` / `SwapBlocker` refuse Here / Locked (above `maxUnlockedLayer`) / Down / Full. Roster UI: drag a portrait (press + 8 px) onto a depth section (move) or another adventurer (swap), ghost at the panel root, green/red `drop-ok` / `drop-bad`, edge auto-scroll; or the depth name on the detail page is a dropdown (`detail-layer`, chevron caret) that opens a picker (locked depths hidden, full ones greyed)
- **Carrying in the world** (`Managers/AdventurerCarry.cs`, on `ClickManager`): hold LMB 0.25 s still on a hero (quick clicks stay clicker attacks) → `AdventurerAgent.SetCarried` pauses its AI tick + walking and the unit hangs under the cursor with sway; label = depth under the cursor (band = floor → floor above, from the managers' `operationArea` strips) green / white own depth / red blocker; release = `Move` (placed at the drop x), own depth = reposition, on a hero of another depth = `Swap`; the released unit falls (`gravity` 60, keeps the swing's sideways speed ≤ `maxThrowSpeed`, clamped to the floor) and lands with dust + a root squash, staying `IsCarried` until down (so it can't be re-grabbed mid-fall); RMB / death / a panel = set back. Moved/swapped-out instances despawn with `despawnQuietly` (no death anim)
- **Rank fit** (`Entities/Adventuers/RankFit.cs`, tuned on `Resources/RankFit.asset`) — gap = rank − depth. Below: −15% damage, +20% damage taken, +25% XP per rank short; above: XP ×0.5 at +1, ×0 from +2, and from +2 (`slackFromRanksAbove`) the unit ignores new targets for 1.5–3 s after each kill (a "zzz" float, no Rogue pursuit) → fewer kills, less loot. `AdventurerAgent.ApplyRankFit` runs on Init, `RestoreProgress` and `Promote` (a depth move respawns); damage is a mediator modifier (ID 5000), damage taken multiplies the class's `damageReduction` in `RefreshDamageTaken`. Roster shows `RankFit.Describe` in `detail-rank-warning`, a tooltip shown while `detail-fit-face` is hovered ("Good fit for this depth" on a fit). Faces: `RankFit.MoodOf` → Outmatched / Stretched / Fit / Easy / Slacking, sprites on `RankFit.faces` (16 px, `Tools/draw_fit_faces.py` → `Sprites/UI/Fit`, thought-bubble palette); shown on the Roster detail (`detail-fit-face`, every mood), Roster slots (`slot-fit-badge`, misfits only) and in the world via `PromoteIndicator`'s "Fit Bubble" — the customers' thought bubble (`RankFit.bubbleFrames`, 3-frame pop-in, scale 0.6, face at half the bubble's texel in its round body); strong moods (outmatched, slacking) keep it up, mild ones (stretched, easy) show it for `mildShowSeconds` (4) after a mood change and while `AdventurerAgent.IsHighlighted` (hovered / Roster-selected); left of the promote badge when both show
- **Promotion follows the fit** — both promote paths (Roster Promote button, class picker for the first promotion) go through `AdventurerManager.PromoteAndFollow(agent, line, out unit, out moved)`: a unit whose depth equalled its old rank moves to the depth of its new rank (via `Move`, so it respawns) when `MoveBlocker` allows it; units placed off-rank on purpose stay. Callers must keep using the returned `unit` (the class picker's callback hands it back); the Roster reselects it (`AfterMove`) and flashes "Moved to <depth>" on the depth line, and the unit floats "Off to Depth N!". Promote fx in two halves: the Roster plays the in-book one (`PlayPromoteFx`: white-out swap, badge slam + sparks); the world one (`ClickHitVFX.QueuePromotion`: gold pillar, `Health.Flash` gold glow, class-name float, then "Off to Depth N!") queues while a panel blocks the world and plays when it clears, so it lands as the book closes. `ChoosePath` (free path pick, rank unchanged) never moves
- Spawn/restore never swaps defs: units spawn with their tier def and `RestoreProgress` replays ranks/levels; `SpawnUnitWithCandidate` joins at `max(startRank, def.rank)`

## Conventions

- **No `Update()` in entity AI** — use `EntityStateMachine` staggered tick (`OnUpdateState`)
- **`TickDelta` must stay bounded** — the staggered tick resets its accumulator to 0 each tick; never go back to `-= UPDATE_INTERVAL` (long frames / high timeScale drift it upward and every AI timer expires on its first tick)
- **Decisive customers** — `CustomerDef.decisiveChance` (Villager 0.1, Herbalist 0.15, Adventurer 0.4, Noble 0.3, Bulk Trader 0.6, Collector 0.8) rolls per visit in `Init`; a decisive customer picks their want when `Entering` ends and goes straight to the line (or straight out on a failed pick) instead of browsing
- **Customers run out of patience** — `CustomerDef.patienceSeconds` (Villager 90, Adventurer 45, Noble 30 …) burns only while they have a want and aren't being served (queue full → browsing again, or standing in line; `CustomerAgent.TickPatience`); the sprite lerps to red over the last quarter (`ApplyTint`, over the state colour) and at zero they leave with `WalkoutReason.Impatient` (hourglass `Sprites/UI/ThoughtBubble/bubble_impatient.png`). Rush Hour / parties overflow the 5-deep queue into walkouts; click-to-serve is the lever
- **Customer walkouts clear the want** — any path that sends a customer to `Leaving` without a purchase nulls `desiredItem`/`desiredQty` and stamps `walkoutReason` first; carry display, the `Upset` anim bool and the reason bubble all key off it (see `CounterService.LeaveNow`)
- **Gold ops** — always go through `Inventory.Instance`, not direct field manipulation
- **Events** — raise via `GameSignals.Raise*()`, never invoke static events directly
- **Stat modifiers** — add via `Stats.Mediator.AddModifier()`, never modify `BaseStats` at runtime
- **Pooled objects** — implement `IPoolable`; call `ObjectPoolManager` instead of `Instantiate`/`Destroy`
- **ScriptableObjects** — data only, no MonoBehaviour logic; use `EntityDef` subclasses for entity config
- **Namespaces** — not used; all classes are in global namespace
- **`[Header]` and `[Tooltip]`** — used extensively in inspectors for designer-friendly fields
- **Debug logs** — use `[ClassName]` prefix convention, e.g. `Debug.Log("[UnitManager] ...")`
- **`showDebugLogs` field** — guard verbose logs with this serialized bool on managers/agents; default to `false`
- **Layer unlock events** — subscribe to `GameSignals.OnLayerUnlocked`; never add a duplicate `OnLayerUnlocked` event to individual managers
- **Query methods must be pure** — never call `RemoveAll` or mutate collections inside `GetUnitCount`, `GetTotalCount`, etc.; null cleanup lives exclusively in `CleanupNullReferences` (runs every 2 s)
- **Dirty flags for frequent checks** — set a `bool pending` flag on high-frequency events (gold earned, loot collected, etc.) and flush once per frame in `Update`; never call an O(n) scan directly from every increment
- **Count before list** — expose a `FooCount` property for callers that only need a count; reserve `GetFoos()` (allocates) for callers that iterate; e.g. `CandidatePool.CandidateCount`
- **Reuse timers** — call `timer.Reset(duration); timer.Start()` on an existing `CountdownTimer` instead of `new CountdownTimer(duration)` on every event
- **Click gold banks on coin arrival** — `ShowGoldGain` owns the gold; it's added via the fly-to-counter arrival callback. Any new failure path in that chain (DamageNumber, ItemExplosionVFX, ItemFlyAnimation) must bank the gold directly — VFX may be skipped, gold is never dropped
- **Pooled visual toggles must be symmetric** — anything a `Show*`/spawn path disables (e.g. `textMesh.enabled`) must be re-enabled by every sibling path; pooled reuse otherwise leaks the off state into unrelated displays
- **Outline rendering-layer bits** — bit 2 = hover/selection (yellow), bit 4 = permanent friendly outline (near-black); world-space markers that shouldn't be stroked must clear these bits on their renderers; bit 8 (`HoverOutlineFeature.OverlayRenderingLayer`) = overlay that hides the outline under it. The outline is composited after every sprite (one Render2D pass, so sorting order can't put anything above it); each feature draws bit-8 renderers into an occluder mask and the composite skips those texels. Damage / gold numbers set it in `DamageNumber.Awake`; give any new overlay that sits over entities the bit
- **Overlay VFX sorting** — `EntitySortingManager` assigns entities orders 2000–8000; screen-feedback particles/markers that must draw over them use order 10000+
- **Body font via token** — `--font-body` in `GlobalVariables.uss` (currently Ithaca); never hardcode a body-font url in USS. Inline UXML styles can't use `var()`, so the few inline font urls (Inventory, Candidate) need manual updates on a font change
- **Clicker upgrade ladders live on `ClickerManager`** — cost/level formulas in code, levels serialized; all purchases raise `OnClickUpgradePurchased` (UI + board badge refresh off it). Game Debugger → Economy has free level set/bump controls
- **New persistent state goes in `SaveData`** — add a chunk to the DTO, fill it in `SaveManager.Collect`, restore it in `ApplyEarly`/`ApplyLate`, then re-raise the existing `GameSignals` so UI rebuilds (no new "loaded" events, no per-component ISaveable). Game Debugger → Save has Save Now / Load / Wipe / Simulate Away
- **ScriptableObject asset names are save keys** — items, milestones, guild upgrades and unit `EntityDef`s are saved by `.name`; renaming one orphans it in existing saves (not restored; only items log an error)
- **Offline rates count passive income only** — customer sales (`OnItemSold`) and porter deliveries (`RecordPorterDelivery`); clicks, milestone claims and debug gold never count. A new income source must decide explicitly whether it's passive
- **Gold in flight rides the save** — gold that's committed but still animating (offline Collect shower) is tracked in `goldInFlight` and saved as banked, decremented per coin on arrival; follow that pattern for any new delayed-bank flow
- **Background play tests need `Application.runInBackground = true`** — an unfocused editor stops advancing frames (Time.frameCount stuck, UITK layout never resolves, `CaptureScreenshot` never writes, scaled timers frozen) while MCP calls still answer; set it in the first play-mode call
- **Editor never saves on pause** — `OnApplicationPause` saves only in builds (`#if !UNITY_EDITOR`; the editor raises pause on focus loss). Autosave (30 s) and quit still save in the editor, so agents still back up `save.json` and call `SaveManager.SuspendSaving()` before play-testing. A pending welcome-back award writes the save as soon as its panel appears (seconds into play, before any MCP call can suspend), so verify with `cmp` afterwards. **Take the backup immediately before each play entry, never reuse one from an earlier test**: the player may have played in the editor in between, and restoring a stale backup over that overwrote real progress once (2026-11-06). If the save moved and the backup isn't from this entry, leave the save alone and ask
- **Dungeon backgrounds are generated, not hand-drawn** — depth 2 `Tools/draw_caverns*.py`, depth 3 `Tools/draw_hollows.py` (`HOLLOWS_MID_OPACITY` / `HOLLOWS_NEAR_OPACITY` env tune the crystal alpha), depth 4 `Tools/draw_catacomb.py` (built to the 24 px adventurer: alcoves 1.5 people, four per tile; stone drawn in the village-house hand — bevelled blocks, corner highlights, near-black joints), depth 5 `Tools/draw_shore.py` (lava sea vista; the far sheet is a 12-frame loop cycled by `Utility/SpriteFrameLoop` at 12 fps, phases 0/4/8; the middle far copy uses `background1-sheet[_f1..11]` with the lavafall, the outer two the `-plain` set without it. Moving pixels (embers, fall streaks) are periodic in y with period = frames × 2 px so the loop point has no jump). Run as `uv run --with pillow --with numpy python3 Tools/<script> <out>`. Only the lower ~126 px of a sheet shows in a band (the rest sits behind the floor above), so content hangs below y≈66. Each depth is three 320×192 / 8 PPU sheets (far opaque wall, mid + near alpha silhouettes) tiled ×3 at 40-unit spacing under `Level Container/Environment/Background - <name>` (`SortingGroup` −25, children groups 1 / 1_01 / 1_02), sheets' bottoms on the depth's `Floor`, clipped by a `Band Mask` `SpriteMask` spanning floor → the floor above. Nested group orders are NOT honoured by the renderer: mid and near groups sit at z −0.05 / −0.1 so they draw over the far wall
- **Transport is per depth** — `Elevator I–V` / `Teleporter I–V` assets are `layerSpecific` save keys (roman numeral = depth, display name "Depth N …"); each ladder's mode = that depth's owned upgrades (`PorterManager.ApplyTransport`), a teleporter leg hops one floor up, never straight to the hall. Elevator = `Elevator_Shaft` sprite, teleporter = ladder hidden + the `Teleport Pad` child (entry dais at the base, its `Teleport Exit` slab on the floor above; activator per depth); a porter stands 0.25 s on the pad before the hop
- **Station defs keep old asset names as save keys** — `Potion Station.asset` is the Smithy, `Crafting Station.asset` the Arcane Workshop; don't rename. `UpgradeType` values are serialized ints, so append new ones only
- **Upgrades may cost materials** — `GuildUpgradeDef.materials` (`RecipeDef.Ingredient` list, empty = gold only) is checked in `CanPurchaseUpgrade` and consumed in `PurchaseUpgrade`, floors ignored like contract hand-ins; station slot k also costs 100×1.5^k of the station's signature raw (Forging StoneChunk / Smithy IronOre / Arcane CrystalShard, `CraftingManager.GetSlotMaterial`/`GetSlotMaterialCost`). Cost chips: `GuildUpgradePanel.MaterialRow`/`MaterialChip` + `.mat-*` in `GlobalVariables.uss`
- **One stock floor** — `Inventory.SetFloor` is the only "keep N"; sales and crafting respect it. Contract hand-ins (`ContractManager.Fulfil`) deliberately ignore it (explicit player action)
- **Crafting display state ≠ `GetBlockReason`** — that's the start gate for a free slot (cap counts jobs in flight); the book derives capped/blocked from stock alone (`CraftingController.StateOf`), the Workshop panel uses `GetSlotState` per slot
- **Slots are the crafting switch** — never add a separate enabled/priority flag; "on" = pinned in a slot. A slot's recipe change cancels and refunds its running job, so a job's recipe always equals its slot's. Crafting saves `slots:{station:[recipe|null]}` + `jobs:[{station, slot, recipe, remaining}]`; pre-3b `enabled` flags migrate into free slots on load (recipes with a running job first) and a job that finds no slot is refunded
- **Don't reimport UXML/USS during a play session** — UITK live reload rebuilds the document tree and controllers holding element refs (Workshop panel, book pages) go stale; restart play to check style edits
- **Stamp overlays sit at page-root level** — the `Stampanim` element is a sibling of left/right content, never inside a page (pages clip overflow); aim it with `BookStamp.AimAt`
- **Crafting right page is height-budgeted** — fits 650px with three 46px ingredient rows and the 56px foot plank 22px off the bottom, no scrolling; growing one block means shrinking another (budget note atop `CraftingPanelStyle.uss`)
- **New pages use `--font-size-body` 24 / `-small` 20 / `-caption` 18** (Ithaca, nothing smaller) — never the legacy `--text-*` scale; Roster + `Components/*.uss` still consume it, so migrate page by page, don't bump it in place
- **Class tier defs are save keys** — the roster saves the adventurer's *current* tier def name; class def asset names (`Bronze Warrior` … `Gold Archmage`, `Lvl 1 Novice`) are final. An unknown adventurer def restores as the Novice (free path pick if above Wood) — never orphaned
- **Class power lives on the tier def, not on promotion** — don't reintroduce per-rank damage/HP modifiers in `AdvanceRank`; tune `damageMultiplier` / `hpMultiplier` on the def (only attack speed still steps per rank)
- **Class rigs are chopped from the Minifolks Humans pack's Aseprite sources** (`/Sprites/minifolks human/*.aseprite`, outside the repo; licensed) by `Tools/chop_minifolk.py <MiniName> <out>` (exports per layer via `/Applications/Aseprite.app`'s CLI into `…/minifolks human/export/`, cached by mtime; routes the `main` + `hands` layers, skips `outline` (the render feature draws one) and lays every other layer — the `slash` trail crescents, the mage's `Layer 1` staff orb / burst — over the weapon sheet as-is (fixed colour, outlined like the weapon; the thief has none in its attack) — and picks frames by tag: idle / walk / attack / damage|hit / death, subsampled evenly): Warrior = MiniHalberdMan, Guardian = MiniShieldMan, Rogue = MiniThief (Villagers pack: pass the full `.aseprite` path; its grey cloak + hood share the beard greys, so they land in the fixed-colour armour / helmet, while the mask and under-clothes recolour — `CLOTH_TONES` lifts its dark cloth to light greys in the shirt / hat sheets, because the Outfit shader desaturates then blends the palette in and dark source cloth comes out near-black), Mage = MiniMage; the Novice keeps the hand-made tunic rig. The roll is `CharacterAppearanceIndices.faceColour` (older saves read 0). `chop_minifolk.py` `BEARD` opts a pack in (colour can't decide it alone: the thief's cloak uses the beard greys) and lifts the dark greys onto the hair sheet's tones; `ROBE` keeps robe cloth out of the weapon (except orb rims touching the crystal / an effect) and out of pants, so a robe recolours as one garment. - **Rank badges live on `ClassCatalog.rankBadges`** (index 0 = Wood … 4 = Gold, `RankBadge(rank)`): `Sprites/Icons/ranks/Rank 1–5`, 2–5 drawn by `Tools/draw_rank_badges.py` (16 px, Wood's shield kept so the rank numeral sits the same; the frame escalates). Roster slots + detail shield, hire posters' `rank-gem` and the world `PromoteIndicator` (the badge of the rank it promotes *into*) all read it — no per-component arrays, no tint on the badge
- **New adventurer classes/tiers go in `ClassCatalog.defs`** — not on a layer manager's `hireableDefs`
- **Class signatures are data on the tier def** — cleave / taunt + damage reduction / crit + pursuit / % max-HP fields on `AdventurerDef` (on iff > 0; edited in the inspector's Behaviour tab → Class section, which shows the def's own class group plus any other group switched on — a new signature field must be added to `EntityDefEditor.DrawClassSection` or it's invisible); resolved in `AdventurerAgent.ResolveHit` via `CombatBehavior.HitOverride`. Splash and other secondary damage go straight to `Health.OnDamage` so procs never chain
- **Rogue pursuit is a hop** — after a kill, a mob within `pursuitRange` (4) gets a `pursuitDashTime` (0.32 s) dash on a `pursuitHopHeight` (0.8) parabola, playing the animator's `Jump` state scrubbed by dash progress, so all 4 frames fit any dash time (`Anims/Adventurers/Jump.anim`, categories `Body/Front Arm/Back Arm Jump` + `Jump`, labels `jump_0..3`). Only the Rogue libraries carry Jump entries (the thief's `jump` tag, chopped with `chop_minifolk.py … --jump`, which puts the row on TOP of every sheet so the existing bottom-up slices don't move). A hop cut short (death) lands the body at the floor height (`dashGroundY`). The Jump state plays whenever the animator has it, hop or not (Gold Nightstalker dashes flat with lightning frames)
- **Class sheet metas have `SpriteEditor.SliceOnImport` off** — when on, Unity re-slices a sheet as a 32 px grid from the top on every import (skipping empty cells → the alpha-1 pad pixels; renaming → new sprite IDs → broken libraries). All `Classes/*` sheets now have it off, so the stored slices are honoured; a new clone of an older sheet (base / tunic / pants / sword metas still have it on) needs it switched off too. Add slices with `ISpriteEditorDataProvider` (keeps existing IDs). Library / clip hashes are `SpriteLibraryUtility.Bit30Hash_GetStringHash` (internal): category and label each hashed, clip keys hash `"Category_Label"` stored as float bits
- **Ranged = a projectile prefab on the tier def** — `AdventurerDef.projectilePrefab` (`Effects/Projectile`, pooled; Mage tiers use `Prefabs/Effects/Fireball`, sprites sliced from `Sprites/Effects/Projectiles/HumansProjectiles.png`, which also holds an unused arrow). `CombatBehavior.Launch` fires it at the shot's `releaseDelay` (the cast's point-forward frame, 0.45 s into the 0.7 s Slash) instead of the melee 0.2 s hit; the shot homes on its target but lands on the first hostile its swept circle touches, through `CombatBehavior.LandHit` (the same path melee uses → procs, numbers, kill XP). A target dead mid-flight = harmless burst at its last spot. Sorting 10000, unlit, flips rather than rotates
- **Mob sprites are Minifolks `.aseprite` files under `Sprites/Mobs/<pack>/`** imported by the Aseprite importer at **8 PPU**, bottom-centre pivot, clips from tags (copy `Orcs/MiniGoblin`'s `m_TextureImporterSettings` + `m_AsepriteImporterSettings`; a sheet left at the default 100 PPU renders ~12× too small, which is why depths 4–5 once looked empty). Each `MobDef` points at an `AnimXxx.overrideController` over `Prefabs/Entities/Mob/Mob Controller` mapping attack / damage (tag `hit` or `damage`) / death / idle / walk / work (= walk). Mob asset names are save keys: re-skin by changing the controller + `displayName`, never the asset name
- **Hover nameplate lives on `ClickerManager`** — one world-space TMP (`nameplate`, sorting 10000, rendering layer 1) over `hoveredAdv`, positioned in `LateUpdate` above the `PromoteIndicator` badge; hidden when dead or `IsBlockingWorldInput`. The right-mouse glyph is a TMP sprite asset like `UpArrow` (`TextMesh Pro/Resources/Sprite Assets/RMB`, `<sprite="RMB" index=0>`); it drops after 3 successful inspects, counted in `ClickerManager.Inspects` and saved in `ClickerSave.inspects`
- **`lastPlayedUtc` means "collected up to", not "last seen"** — while a welcome-back award is unclaimed it's saved as `now − pendingAway` and rates freeze, so quitting on the panel re-offers the identical award; don't "fix" it to `UtcNow`
